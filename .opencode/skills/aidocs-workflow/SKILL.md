# aidocs-workflow

围绕 `.aidocs` 设计思想的可复用开发流程 skill。覆盖 AI 开发全流程，最终产出**结构化文档**而非一次性对话，从而沉淀经验、支持跨项目复用提示词。

## 1. 核心原则

1. **流程纪律**：多步骤任务按"理解 → 澄清 → 验证 → 设计 → 实现 → 测试 → 沉淀"推进，不跳步、不臆测。
2. **文档即产出**：任务结束后的文档与代码同等重要；没有沉淀的任务等于没完成。
3. **先确认后动手**：关键决策先用 `question` 工具与用户确认方向，再开始执行。
4. **验证优先**：前提不成立的方案不要实现，先小成本验证。

## 2. .aidocs 目录规范

```
.aidocs/
├── *.md               # AI 生成的综合文档（根目录）
├── archive/           # 历史/存档信息（过时或阶段性的方案、决策、记录）
└── <project-name>/    # 与项目同名，记录细节信息（单任务分析、设计、过程记录）
```

| 位置 | 放什么 | 示例 |
|------|--------|------|
| 根目录 | 跨任务、面向全项目的综合文档 | `project-guide.md`、`troubleshooting-record.md`、`reverse-engineering-review.md` |
| `<项目名>/` | 单个任务/主题的细节文档 | `post_articles_aggregations.md`、`bucket-crawl-implementation-record.md` |
| `archive/` | 已被替代/过时的方案与记录 | 旧版设计、已废弃决策 |

规则：
- **根目录文档由 AI 生成，子目录给开发者二次精选整理**（开发者可在 AI 文档基础上提炼）。
- 综合文档与细节文档分层：细节沉到 `<项目名>/`，需要全项目引用的提炼到根目录。
- 新文档必须**交叉引用**相关已有文档，避免信息孤岛。
- 历史价值低的旧内容移入 `archive/`，不随手删除。

## 3. 全流程工作法

### 阶段 0：理解需求
- 先读 `.aidocs/` 已有文档（`project-guide.md`、`troubleshooting-record.md`、`task.md`、README 等）再动手，不要凭直觉猜项目结构。
- 用自己的话重述需求，确认理解一致。

### 阶段 1：澄清确认
- 遇到方向性决策（方案选型、范围、约束、存储位置等），用 `question` 工具给出选项 + 推荐项，等用户确认。
- 记录用户的关键约束（例如：只改某模块、保留旧功能、覆盖率不必 100%）。

### 阶段 2：验证
- 复杂/有风险的前提先小成本验证（连通性、接口限制、窗口上限、可行性），把结论写清楚再继续。
- 验证结论要可复现（记录命令、数据、数字）。

### 阶段 3：设计
- 给出设计方案 + 路线规划（分阶段），让用户确认后再写代码。
- 设计要落到文档（存到 `<项目名>/` 或根目录），方便后续追溯。

### 阶段 4：实现
- 遵循项目现有代码约定；改动可运行后自测。
- 过程中遇到的坑、临时结论，及时记录，避免遗忘。

### 阶段 5：确认 / 调整 / 反馈循环
- 实现后向用户汇报：改了什么、验证结果、遗留问题。
- 根据用户反馈调整，重复直至确认。

### 阶段 6：沉淀文档
- 任务完成后，按第 2、4 节规范写文档（总结 + 细节并存）。
- 同步更新综合文档（`project-guide.md` 版本号/变更记录、`task.md` 完成项）。
- 提醒用户：是否提交代码/文档（不擅自 commit）。

## 4. 文档写作规范

- **元信息**：文档开头给版本/日期/关联文档；长文加目录。
- **总结 + 细节并存**：既有结论性表格/摘要，也有实现细节（命令、代码位置、数字）。
- **结构清晰**：用表格、分节、代码块；避免大段无结构文本。
- **变更记录**：综合文档维护变更记录（日期/版本/内容）。
- **交叉引用**：新文档链接相关已有文档。

## 5. 跨项目复用

本 skill 可整体复制到其它项目（连同 `scrapy-debugging`、`crawler-debugging`），用法：

1. 复制 `.opencode/skills/` 目录到目标项目（或安装到 `~/.config/opencode/skills/` 全局生效）。
2. 按需把"项目示例"替换为目标项目场景。
3. 用 `project-guide.md` 的 `.aidocs` 结构初始化目标项目的文档骨架。
4. 修改配置后需**重启 opencode** 生效。
