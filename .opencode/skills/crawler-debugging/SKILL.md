# crawler-debugging

API 爬虫调试的通用方法论，核心是**验证优先**：先探测接口与限制，再写代码。附带本项目（pubscholar.cn 爬虫）实例作为参考，可复制到其它爬虫项目复用。

## 1. 验证优先原则

写任何爬虫代码之前，先回答：

1. 接口是否连通？HTTP 状态与签名是否正确？
2. 认证需要什么（Cookie / Token / 签名头 / 请求头完整性）？
3. 是否有分页/频率限制？上限是多少？换查询参数后是否重置？
4. 数据字段结构是否与预期一致？（先打印一小段真实响应）

## 2. 接口验证四步

1. **连通性**：最小请求打接口，看 HTTP 200 + 响应结构。
2. **签名/逆向**：若需签名，从抓包拿到真实参数（nonce/timestamp/signature），用已知数据回测算法，100% 匹配再继续。
3. **请求头完整性**：逐一补齐浏览器同源请求头（`Sec-Fetch-*`、`Origin`、`Referer`、`User-Agent`），服务器可能多因素组合校验。
4. **认证**：CSRF Token（`XSRF-TOKEN` Cookie + `X-XSRF-TOKEN` Header）、会话 Cookie 缺一不可。

## 3. 分页窗口限制探测

- 用不同 `page_size` 探测边界，判断限制基于**页码**还是 **offset（page×size）**。
- 超限响应特征（示例）：HTTP 200 但 `{"total":0,"is_last":true,"content":[]}`，且 `total_pages=0`——与"自然结束"区分。
- **关键问题**：换过滤条件（组合参数）后窗口是否重置？重置则可用"分桶遍历"突破上限。

## 4. 聚合分桶遍历（突破窗口限制）

当单查询有上限（如 offset 10000），且接口提供聚合/筛选维度时：

1. **维度完备性分析**：调聚合接口，看各维度计数之和占总数的比例。
   - 覆盖 ~100% 的维度（如年份）可做完整划分；
   - 被 top-N 截断的维度（如学科）只能部分覆盖，残差按需求接受或另想办法。
2. **递归切分**：顶层固定约束（如 collection + lang）→ 按 `year → subject → source` 逐级切分，直到每桶命中数 ≤ 阈值。
3. **翻页边界**：每桶 `max_page = min(ceil(total/size), threshold//size)`，桶内滑窗翻页。
4. **断点续爬**：每桶参数做稳定哈希（query_hash）幂等入库，状态 pending/running/completed；重启续爬。
5. **去重**：桶间可能有重叠，用统一去重键（如 DOI / 标题+来源+年份哈希）兜底。

参考本项目：`verify_window_limit.py`（窗口探测 + 分桶可行性预览）、`utils/query_plan.py`、`utils/query_state.py`、`.aidocs/academic-spiders/bucket-crawl-implementation-record.md`。

## 5. 数据质量检查

- 字段类型/长度：长日期存 `VARCHAR(10)` 会溢出 → 解析器截断；先看落库错误日志。
- 缺失字段：部分记录某字段可能为空（站点数据问题），如实存储，不要臆造。
- 用 `COUNT`/`GROUP BY` 抽查落库数据验证管道正确。

## 6. 通用调试顺序

1. 最小请求验证连通与签名。
2. 探测限制（窗口/频率）并记录结论。
3. 小范围跑通（限页/限桶）。
4. 验证数据与去重。
5. 放开规模并支持断点续爬。

## 7. 跨项目复用

复制本 skill 到目标爬虫项目，把"聚合接口/窗口/分桶"实例替换为目标接口的实际情况即可。
